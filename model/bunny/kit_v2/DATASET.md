# Purple bunny dataset (white background, 64 / 96 / 128 px RGB)

Generated by `make_dataset.py` from the layered vector rig in `bunny_rig3.py`. Deterministic: same seed, same frames.

## Files
- `bunny_rig3.py`  the rig: 32 dials -> image. `DIAL_NAMES` fixes the input order for the NN.
- `clips.py`       19 motion clips (idle, look, hop, walk, run, wave, shake, lie_down, sleep, sit, yawn, sad, eat, love, stretch, clap, angry, dizzy, confused). Also the runtime motion library for the CPU.
- `make_dataset.py` renders the set: `python make_dataset.py OUT.npz N SIZE [SEED] [WORKERS]`
- `bunny_train_<size>.npz`: `images` uint8 [N,size,size,3], `dials` float32 [N,32], `tags` (clip name or "a>b" for transitions, "random"), `dial_names`, `val_mask` (5% validation).

## The 32 input dials (NN input order)
Eye weights (5, sum to 1): open, wide, happy, sleep, sad
Mouth weights (6, sum to 1): smile, open, o, flat, frown, yawn
Scalars (21): ear_l, ear_r, curl, ear_len, look_x, look_y, arm_l, arm_r, foot_l, foot_r, squash, tilt, lie, head_tilt, blush, tear, hue, sat, head_scale, brow, dizzy
Normalise each scalar to [0,1] with its (lo, hi) range from `SCALARS` in bunny_rig3.py before feeding the NN.

## What is NOT in the NN (CPU side)
Screen position, hop height, flip left/right, and effects (zzz, sweat, hearts). Images are the bunny only, on white.

## Sampling mix
55% frames from coherent clips (random time, amplitude 0.75-1.15), 25% blends between two clips (transition coverage), 20% random dials with U-shaped sampling so extremes are well covered (arms raised, ears flat, lying down). Every sample also gets random identity dials (hue, sat, ear_len, head_scale) and small noise on all dials.

## Training notes
- Plain conditional decoder: dials -> small MLP -> reshape -> a few upsampling conv blocks (resize + conv, no transposed conv) -> sigmoid RGB. L1 (plus a little MSE) loss. Weighting edge pixels higher helps keep the outline crisp.
- Target 64x64 or 96x96 output. Check int8 quantisation early (outline thickness at 64x64 is ~3px).
- Check Vela/NPU delegation 100% before training long. Avoid ops that fall back to CPU (e.g. avoid transposed conv if it does, avoid GroupNorm/InstanceNorm, prefer BatchNorm folded or none).
- Hold out `val_mask` and evaluate on in-between dial values, not only on training frames.

## Resolution notes
- Read the dial count and order from `dial_names` in the .npz, never hard-code it.
- `train_bunny.py DATA.npz --size S` trains the decoder (start grid S/16, four x2 blocks). Works on CPU or a GPU; it checkpoints every epoch and writes `dial_ranges.json` (the firmware must normalise dials with those lo/hi values).
- Rendering is deterministic and fast (about 5 min per 40k images on 2 cores at 96 or 128), so any size can be re-rendered anywhere instead of uploading a big file.
